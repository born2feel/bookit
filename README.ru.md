Бот для небольшого бизнеса с одним мастером: барбершопа, репетитора, массажиста.
Клиент выбирает услугу, дату и свободное время, администратор управляет каталогом,
записями и выходными прямо в Telegram. Интерфейс доступен на **русском и английском**.

## Возможности

**Клиент**
- 📅 Пошаговая запись: услуга → дата → свободный слот → подтверждение с ценой
- 📋 «Мои записи»: предстоящие записи с отменой в два нажатия
- 🔒 Бот не даст записаться в прошлое, на выходной или на занятое время
- 🌐 Выбор языка (🇷🇺 Русский / 🇬🇧 English). При первом визите язык берётся из настроек Telegram, потом пользователь меняет его кнопкой или командой `/language`.

**Администратор** (`/admin`, доступ по `ADMIN_IDS`)
- 🧾 Услуги: добавление, изменение цены и длительности, скрытие из каталога
- 📅 Записи на любую дату с возможностью отмены (клиент получает уведомление)
- 🌴 Выходные дни. Бот не даст закрыть день, на который уже есть записи.
- 🔔 Уведомления о новых записях и отменах, каждому на его языке

## Архитектура

```
Telegram ──► handlers ──► services ──► repositories ──► БД
             (aiogram)    (логика)     (SQLAlchemy)
```

- **handlers** (`bot/handlers`): принимают апдейты, вызывают сервисы и рисуют ответ. В БД напрямую не ходят.
- **services** (`services/`): вся бизнес-логика: расчёт слотов, правила записи и отмены, валидация. Слой не зависит от языка. Доменные ошибки (`BookItError`) несут ключ перевода и параметры, а текст собирает слой бота.
- **repositories** (`repositories/`): только SQL-запросы, без бизнес-правил.
- **middleware** открывает сессию БД на каждый апдейт и через DI aiogram внедряет в хендлеры сервисы, переводчик (`tr`) на языке пользователя и уведомитель.
- **Обработка ошибок** собрана в одном месте: доменные ошибки показываются пользователю понятным текстом на его языке. Неожиданные ошибки пишутся в лог, а пользователь видит нейтральное сообщение.

### Интересные решения
- **Расчёт слотов** вынесен в чистую функцию `compute_free_slots`: рабочие часы, шаг сетки, длительность услуги, пересечения полуинтервалов `[start, end)`, отсечение прошедшего времени.
- **Защита от двойной записи на двух уровнях.** `asyncio.Lock` делает атомарными проверку и вставку (aiogram обрабатывает апдейты конкурентно). В БД стоит частичный уникальный индекс `start_at WHERE status = 'active'`, он работает и в SQLite, и в PostgreSQL.
- **Время** хранится в UTC: тип `UTCDateTime` выравнивает поведение SQLite и PostgreSQL. Показывается время в часовом поясе бизнеса.
- **i18n без зависимостей:** словари сообщений `bot/i18n/{ru,en}.py`. Тесты проверяют, что в обоих языках одинаковые ключи и плейсхолдеры, а каждый ключ из кода существует.
- **Часы в сервисах подменяемые** (`clock`), поэтому тесты детерминированы.

### Структура
```
src/bookit/
├── __main__.py        # точка входа
├── config.py          # настройки из окружения
├── db/                # модели, базовый класс, сессии
├── repositories/      # доступ к данным
├── services/          # бизнес-логика + доменные исключения
└── bot/
    ├── handlers/      # common, client, admin, errors, fallback
    ├── keyboards/     # inline-клавиатуры
    ├── i18n/          # переводы ru / en + Translator
    ├── callbacks.py   # CallbackData-фабрики
    ├── states.py      # FSM
    ├── middlewares.py # сессия БД + DI
    ├── filters.py     # IsAdmin
    └── notifier.py    # уведомления
migrations/            # Alembic
tests/                 # тесты
```

### Модель данных
- **User**: пользователь Telegram и его язык интерфейса
- **Service**: услуга (название, длительность, цена, активна ли)
- **Booking**: запись (клиент, услуга, начало, конец, статус `active`/`cancelled`)
- **DayOff**: выходной день

## Запуск локально

Нужен Python 3.12+.

```bash
git clone https://github.com/born2feel/bookit.git
cd bookit
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
cp .env.example .env             # заполните BOT_TOKEN и ADMIN_IDS
alembic upgrade head
python -m bookit
```

## Запуск через Docker

```bash
cp .env.example .env             # заполните BOT_TOKEN, ADMIN_IDS, POSTGRES_PASSWORD
docker compose up --build -d
docker compose logs -f bot
```

Поднимутся PostgreSQL и бот. Миграции применяются автоматически при старте контейнера.

## Конфигурация

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | (обязательно) | токен от @BotFather |
| `ADMIN_IDS` | (пусто) | Telegram ID админов через запятую |
| `DATABASE_URL` | `sqlite+aiosqlite:///./bookit.db` | строка подключения SQLAlchemy |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс бизнеса |
| `WORK_START` / `WORK_END` | `10:00` / `20:00` | рабочие часы |
| `SLOT_STEP_MINUTES` | `30` | шаг сетки слотов |
| `BOOKING_HORIZON_DAYS` | `14` | на сколько дней вперёд можно записаться |
| `LOG_LEVEL` | `INFO` | уровень логирования |

## Тесты и линтер

```bash
pytest
ruff check .
ruff format --check .
```

Тесты покрывают слой services: расчёт слотов, создание и отмену записей, каталог,
выходные, языки пользователей, валидацию ввода и конфиг. Отдельные тесты проверяют
каталоги переводов. Каждый тест работает на своей SQLite-базе в памяти.
CI (GitHub Actions) на каждый push и PR запускает линтер, форматтер, тесты и проверку того,
что миграции соответствуют моделям (`alembic check`).

## Ограничения

- Один мастер: расписание общее для всех услуг.
- FSM хранится в памяти (`MemoryStorage`), поэтому при перезапуске незавершённые сценарии сбрасываются.
- Блокировка записи работает в пределах одного процесса бота. Это нормально для long polling,
  где бот всегда запущен в одном экземпляре.

## Безопасность

Секреты читаются только из переменных окружения, `.env` исключён из git и Docker-образа.
Админ-хендлеры защищены фильтром, пользовательский ввод экранируется, контейнер работает не от root,
а Dependabot следит за обновлениями зависимостей. Как сообщить об уязвимости, описано в [SECURITY.md](SECURITY.md).
